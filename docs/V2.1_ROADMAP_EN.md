# Zap v2.1.0 Roadmap

## Release theme

> Reliable packages, a richer standard library, and structured concurrency.

Zap v2.1.0 is the next feature release after the production-hardening focus of v2.0.3. The first implementation slice strengthens package resolution while preserving Rust 1.75 compatibility, deterministic ordering, bounded I/O, and stable diagnostics.

## Completed v2.1-A slice

Registry index entries may now include an optional `dependencies` object:

```json
{
  "name": "web-app",
  "version": "1.0.0",
  "source": "file://web-app.pkg",
  "checksum": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "dependencies": {
    "http-core": "^1.2.0"
  }
}
```

Zap visits root requirements and nested requirements in lexical order. For each package name it selects the highest compatible registry version, keeps one version per graph, and returns the resolved set in deterministic package-name order. A cycle or incompatible repeated requirement is rejected with a deterministic diagnostic. `zap install` and `zap update` then verify existing cache entries or download and verify every selected package, subject to the configured timeout, transport, checksum, and offline policies.

The implementation is covered by native tests for transitive selection, stable result ordering, cycle detection, and version conflicts. Existing indexes without `dependencies` remain valid, so the change is backward-compatible with the v2.0.3 registry format.

## Next implementation order

### v2.1-B: Package reliability

1. Extend lockfile representation to record resolved registry packages and checksums without breaking v1 lockfiles. **Completed:** v2 emits deterministic `[resolved]` entries and v1 remains readable.
2. Add a migration/compatibility diagnostic for projects that require a newer lockfile format. **Completed:** `zap lock-migrate` is explicit, conservative, deterministic, and refuses to invent registry metadata.
3. Make `zap install` report the complete resolved graph rather than only direct manifest dependencies. **Completed:** output preserves the established count prefix and appends the complete deterministic `name@version` graph.
4. Expand offline integration fixtures with nested packages and missing-cache diagnostics. **Complete for the current slice:** fixtures now cover nested transitive resolution, missing transitive cache artifacts, cached checksum mismatches, and incomplete v2 lockfiles with stable diagnostics; additional transport and registry-service failure paths remain future work.
5. Add registry cache garbage collection with explicit dry-run output and deterministic deletion order. **Completed for the first slice:** `zap registry gc [--dry-run] [dir]` derives keep entries from a canonical lockfile, preserves referenced artifacts, removes stale and temporary files in lexical order, and refuses invalid lockfiles.
6. Define authentication and trusted-registry policy separately from the transport layer. **Transport/service failure slice completed:** insecure HTTP is rejected by default, malformed remote indexes have stable diagnostics, and non-2xx fetch/publish responses are normalized to deterministic HTTP-status errors. **B1/B2 implementation slice completed:** canonical origins, bounded trusted-registry policy, persistent `zap registry trust list|add|remove`, origin-scoped bearer credentials, bounded credential configuration through `zap registry credential list|set|remove`, token validation/redaction, stable `ZAP-REG-AUTH-001`/`002`/`003` diagnostics, and effective-policy enforcement across dependency resolution and registry fetch/cache/publish paths are implemented. Remaining acceptance work covers final documentation/release review and cross-platform release integration.

### v2.1-C: Standard library expansion

**First slice completed:** `file_metadata(path)` returns portable `kind`, byte `size`, and `readonly` fields using symlink-safe metadata, while `atomic_write(path, content)` uses a same-directory temporary file, sync, and rename commit with bounded content and cleanup on failure. **Second slice completed:** `from_json_typed(source, expected)` validates the decoded runtime category under the existing 8 MiB JSON limit, while `char_at`, `substring`, and `codepoints` operate on Unicode scalar values rather than UTF-8 byte offsets. **Third slice completed:** `entries(value)` returns deterministic `{key, value}` map records and `enumerate(values)` returns bounded `{index, value}` list records without mutating the input. **Fourth slice completed:** `utc_now()` returns UTC seconds and millisecond timestamps, while `duration_parts(milliseconds)` and `duration_between(end_millis, start_millis)` provide signed, checked duration decomposition with overflow diagnostics. Focused regression tests cover timestamp consistency, positive and negative durations, and invalid inputs. **Fifth slice completed:** `log_record(level, message, fields)` returns a validated structured map and `log_json(level, message, fields)` returns canonical JSON with sorted field names. Logging is pure and deterministic, with an 8 KiB message limit, 64-field limit, 256-byte field-name limit, and 64 KiB encoded-output limit. Regression tests cover canonical ordering, accepted levels, validation errors, and safety limits. The v2.1-C standard-library slice is complete; each future API must define input limits, output limits, timeout behavior, platform differences, and error codes before implementation.

### v2.1-D: Async and tooling

**First async slice completed:** the deterministic single-threaded async runtime supports `AsyncRuntime::spawn_joinable(future)`, `JoinHandle<T>::is_ready()`, and future-based output joining with explicit `SpawnError::TaskLimitReached` propagation. **Second async slice completed:** `AsyncRuntime::spawn_joinable_cancellable(future)` provides structured cancellation through `CancellationToken`, cancelled joins resolve to `JoinError::Cancelled`, and `timeout_ticks(future, ticks)` propagates deterministic poll-based `TimeoutError` results. **Third async slice completed:** `spawn_joinable_result(future)` and `spawn_joinable_result_cancellable(future)` preserve typed task failures through `TaskJoinError::Failed(E)`, with cancellation checked before inner polling and repeated joins returning `AlreadyJoined`. These slices preserve runtime task order, poll budgets, Rust 1.75 compatibility, and the no-worker-thread safety model. Regression coverage verifies successful joins, admission errors, typed failures, cancellation precedence, repeated joins, timeout failure, and timeout success; the bilingual contract is documented in `docs/ASYNC_RUNTIME_EN.md` and `docs/ASYNC_RUNTIME_MM.md`.

**Fourth async slice completed:** the evaluator and legacy expression path now expose `spawn`, `task_join`, and `task_is_ready` over the existing `Future` value contract. The facade validates arity and input types, preserves the eager deterministic Future boundary, and rejects non-Future joins with stable diagnostics. End-to-end regression coverage verifies async spawn, readiness, joining, and invalid task inputs; `docs/ASYNC_RUNTIME_EN.md`, `docs/ASYNC_RUNTIME_MM.md`, `docs/ASYNC_LSP_EN.md`, and `docs/ASYNC_LSP_MM.md` document the synchronized contract.

**Tooling synchronization completed:** formatter behavior, LSP completion/hover/signature/formatting support, and VS Code grammar validation now track the finalized async task vocabulary. `spawn`, `task_join`, and `task_is_ready` are exposed consistently in editor completion and TextMate highlighting, with smoke coverage preventing grammar drift. The LSP now advertises `textDocument/documentSymbol` and recursively returns nested function and class declarations with deterministic ranges and children; regression coverage verifies nested symbols in both class and function bodies. The module-aware package indexing slice is also complete: workspace symbols safely follow explicit local imports, canonicalize and bound imported files, reject traversal-like paths, deduplicate nested modules, and return deterministic symbols from unopened local package files. The production async slice is now complete for the bounded standard-library adapter: `ThreadedRuntime` provides a fixed worker set, task admission limits, wakeable cross-thread joins, panic-to-error conversion, capped asynchronous regular-file reads, bounded non-blocking TCP request/response exchange, and asynchronous process execution with deadline and output limits. Regression coverage includes socket round trips, oversized responses, cross-platform process output, and capped process output. Forced process cancellation is now implemented for cancellation-aware child execution: cancellation or deadline terminates the child, drains bounded output, and resolves deterministically without claiming arbitrary foreign blocking calls can be interrupted. Network registry service deployment is also complete for the controlled local slice: authenticated loopback HTTP service operation, bounded request parsing, safe in-root paths, atomic signed-index persistence, managed shutdown, and deterministic unauthorized/traversal/malformed/oversized-request failures are covered. Public production deployment still requires TLS termination, ingress policy, external supervision, OS-level sandboxing, resource quotas, least-privilege credentials, and network egress controls.

### v2.1-E: Release engineering

The first security-audit remediation slice is complete: `ZAP_UNTRUSTED=1` restricted capability mode, SSRF destination checks, disabled automatic redirects, bounded HTTP request bodies, hard process deadlines, and local registry-source restrictions are implemented and covered by regression tests. The full audit record is documented in `docs/SECURITY_AUDIT_EN.md` and `docs/SECURITY_AUDIT_MM.md`.

The v2.1-E security-property slice is also complete. A deterministic adversarial corpus now checks URL-origin normalization idempotence, rejection of credentials/query/fragment/traversal/separator/whitespace inputs, trust and credential scope boundaries, the bounded 64-origin allowlist, longest-prefix credential selection, token validation, secret redaction, and signed-index mutation handling. The signed-index corpus executes malformed and byte-mutated inputs through `catch_unwind`, requiring parser errors rather than panics or tampered-index acceptance. These checks run as an explicit `security_property` CI step in addition to the complete native test suite.

The production deployment reference slice is complete. `deploy/zap-registry.service` provides supervised least-privilege Linux execution with protected filesystem paths, explicit writable storage, memory/CPU/task/file quotas, and loopback-only network access. `deploy/zap-registry.nginx.conf` provides TLS 1.2/1.3 termination, HTTP-to-HTTPS redirect, bounded request bodies and proxy timeouts, restricted methods, and a loopback upstream. `deploy/registry.env.example` contains placeholders only, `deploy/registry-deployment-policy.toml` records the credential/sandbox/quota/egress contract, and `scripts/validate_registry_deployment.sh` verifies the artifacts without exposing secrets. CI runs this deployment-policy gate independently. Repository-side controls are therefore complete; public operations still require real certificate/DNS/ingress provisioning, external supervision, monitoring, OS-native sandbox equivalents, and an explicitly reviewed egress allowlist.

Workspace-confined filesystem policy and symlink-safe canonicalization are now implemented at the runtime filesystem boundary. Relative and absolute file paths are resolved against the active project workspace, parent traversal is rejected, and existing symlinks are canonicalized before the containment check so links cannot redirect reads or writes outside the workspace. Dedicated regression coverage exercises traversal and outside-workspace symlink attacks, and CI runs the `filesystem_builtins` corpus independently of the complete native suite.

The lexer, parser, JSON conversion, and lockfile hardening corpus is now complete. Deterministic malformed-input tests cover huge numeric literals, unterminated strings, unknown punctuation, malformed indentation and delimiters, broken nested syntax, malformed tagged JSON variants, oversized integer values, unsupported lockfile versions, incomplete or duplicate lockfile fields, invalid escapes, traversal-like package names, and strict quoted-value handling. Each corpus repeats parsing/conversion under `catch_unwind`, requiring no panic and stable results for identical input; JSON and lockfile checks additionally require deterministic conversion or rejection. CI runs the dedicated `adversarial_corpus`, `malformed_program_corpus`, `json_security_corpus`, `malformed_lockfile_corpus`, and `lockfile_quoted_values` filters independently. Deterministic Unix release packaging is enforced by normalized archive member ordering, timestamps, ownership, numeric ownership, and gzip metadata. Windows packaging now uses a deterministic .NET ZIP writer with sorted slash-separated entries, fixed Unix-epoch entry timestamps, stable compression settings, and a second byte-for-byte rebuild check; archive contents and SHA-256 checksums remain verified. Installer verification is now implemented for clean Unix homes and Windows user profiles. The release package includes uninstall scripts; CI verifies install, version reporting, execution, reinstall/upgrade, uninstall cleanup, archive contents, and SHA-256 metadata on the matching platform. Remaining hardening boundaries are broader corpus expansion and production deployment controls. An additional standard-library adversarial corpus now exercises oversized typed-JSON input, runtime category mismatches, Unicode index boundaries, duration overflow, structured-log level/message/field limits, and oversized atomic-write content. Each case is executed twice under `catch_unwind`, requiring stable rejection without a panic; the dedicated `stdlib_security_corpus` CI gate runs independently of the complete native suite.

Public production operations must additionally provision platform-native certificate management, DNS and ingress/WAF/rate limiting, external supervision and monitoring, OS-native sandbox equivalents, and a reviewed network egress allowlist. The repository's reproducible reference artifacts and validation gate cover the deployment contract without performing a public deployment or storing secrets.

## Release gates

A v2.1.0 release requires a clean working tree, Rust 1.75-compatible builds, complete native tests, strict Clippy, deterministic smoke fixtures, cross-platform target-native execution, verified checksums, and synchronized English/Burmese documentation. No feature should be marked complete solely because it works on Linux; Windows and macOS behavior must be covered by CI or an explicit documented limitation.
